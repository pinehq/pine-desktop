# Pine Desktop for Linux

> Нативное Linux-приложение для работы с CLI-агентами, кодом, Git и
> несколькими параллельными задачами в одном наблюдаемом рабочем пространстве.

Проект находится на стадии первого vertical slice. Он вдохновлён
[Pine](https://github.com/batonogov/pine), но не является механическим переносом
SwiftUI/AppKit-кода. Linux-реализация строится вокруг GTK4, GtkSourceView и
сменного terminal backend, а переносимая продуктовая логика пишется на Rust.

## Продуктовая идея

Агент остаётся обычным CLI-процессом в настоящем терминале. Приложение не
заменяет его собственным чатом, а объединяет рядом:

- редактор и навигацию по проекту;
- встроенный GPU-терминал;
- Git status, diff, branch и worktree;
- LSP-диагностику и навигацию по коду;
- глобальный Agent Inbox для задач из разных проектов;
- проверяемые изменения, тестовые свидетельства и безопасное восстановление.

Основная формула продукта:

> Агент работает в терминале. Код остаётся перед глазами. Пользователь сохраняет
> контроль над процессом и изменениями.

## Принципы

- **Native GNOME.** GTK4/libadwaita и GNOME HIG вместо Electron, WebView или
  копирования macOS-паттернов.
- **Terminal first.** CLI-агенты запускаются без подмены их интерфейса.
- **Local first.** Код, терминальные процессы и метаданные задач остаются на
  машине пользователя.
- **Observable, not autonomous.** Приложение наблюдает, маршрутизирует и
  проверяет, но не планирует работу агентов без явного действия пользователя.
- **Evidence over inference.** Завершение процесса не означает успешное
  выполнение задачи.
- **Isolation by default.** Параллельные задачи могут получать отдельные Git
  worktree.
- **Portable core.** Модель задач, Git, LSP и адаптеры не зависят от GTK, чтобы
  в будущем их могла использовать Windows-версия.

## Предлагаемый стек

| Область | Решение |
| --- | --- |
| Интерфейс | GTK4/libadwaita, API floor Ubuntu 24.04 (4.14/1.5) |
| Редактор | GtkSourceView 5 |
| Терминал MVP | VTE 4 за toolkit-neutral контрактом |
| Целевой терминал | `libghostty-vt` + собственный GTK/GSK renderer |
| Доменное ядро | Rust |
| Асинхронная работа | GLib main loop для UI, Tokio для фоновых сервисов |
| Git | безопасный запуск `git` без shell-интерполяции |
| LSP | JSON-RPC клиент поверх stdio |
| Хранение задач | SQLite с транзакциями и миграциями |
| Linux-интеграция | `/proc`, XDG, D-Bus/portals, позднее systemd user service |

## Предполагаемый интерфейс

Главное окно состоит из следующих областей:

```text
┌────────────────────────────────────────────────────────────┐
│ Project / Worktree       Quick Open          Agent Inbox   │
├──────────────┬─────────────────────────────────────────────┤
│ Files        │ editor.swift                     editor tab │
│ Git          │                                             │
│ Agents       │               Editor / Diff                 │
│              │                                             │
│              ├─────────────────────────────────────────────┤
│              │ agent: codex · task: linux-ui     terminal │
│              │                       VTE MVP               │
├──────────────┴─────────────────────────────────────────────┤
│ branch · worktree · diagnostics · agent status · cursor   │
└────────────────────────────────────────────────────────────┘
```

Редактор, diff и терминал должны размещаться в split-панелях. Agent Inbox может
открываться как компактный overlay и как отдельное глобальное окно.

## Первая версия

Минимально полезная версия включает:

1. открытие проекта и дерево файлов;
2. редактирование через GtkSourceView;
3. один встроенный VTE-терминал за сменным `pine-terminal` API;
4. Git status и просмотр diff;
5. запуск поддерживаемого CLI-агента в выбранной директории;
6. связь `Task → Run → Terminal → Process`;
7. Agent Inbox внутри одного процесса приложения;
8. создание изолированного worktree для новой задачи;
9. сохранение и восстановление метаданных сессии.

На первом этапе приложение не обещает продолжение терминальных процессов после
полного выхода из UI. При активных задачах выход должен требовать явного решения
пользователя. Фоновый supervisor рассматривается отдельным этапом.

## Запуск MVP

Целевые среды — Ubuntu 24.04 и 26.04 LTS. После установки системных development
packages:

```sh
cargo run -p pine-linux
```

Точные N‑1 версии Rust-компонентов и команды для Ubuntu описаны в документации
разработки.

## Источники и вдохновение

- [Pine](https://github.com/batonogov/pine) — продуктовая модель нативного
  редактора для CLI-agent workflow.
- [Ghostty](https://github.com/ghostty-org/ghostty) — terminal state для
  будущего собственного renderer и пример разделения ядра и нативных оболочек.
- [GTK4](https://docs.gtk.org/gtk4/) и
  [GtkSourceView 5](https://gnome.pages.gitlab.gnome.org/gtksourceview/gtksourceview5/)
  — основа Linux-интерфейса и редактора.

При заимствовании кода, ресурсов или тестовых фикстур лицензии и attribution
соответствующих upstream-проектов должны сохраняться отдельно от общей идеи и
архитектуры продукта.
