# ADR 0002: нативные .deb-пакеты и собственный APT-репозиторий

- Статус: принято
- Дата: 2026-08-12

## Контекст

Pine Desktop — нативное GNOME-приложение на GTK4 (см. ADR 0001). Его core-
инварианты — «CLI-агент остаётся реальным процессом в реальном PTY», а также
прямой доступ к Git-командам и файловой системе пользователя на host — прямо
конфликтуют с изоляцией sandbox-упаковок. Это зафиксировано в ADR 0001:
ограничение реализации №6 запрещает незаметно ослаблять process и filesystem
проверки через packaging, а условие пересмотра прямо отвергает sandbox, если
он делает host CLI workflow практически невозможным.

Нужно выбрать стратегию дистрибуции, автообновлений и автоматизации релизов
для поддерживаемых LTS — Ubuntu 24.04 и 26.04 — не нарушая эти инварианты.

Главная развилка — sandbox-упаковка (Flatpak), каноничный Ubuntu-канал (PPA)
или нативные пакеты, собираемые и распространяемые самостоятельно.

## Решение

1. Выпускать Pine Desktop как нативные `.deb`-пакеты через `cargo-deb`.
2. Раздавать пакеты через собственный APT-репозиторий, хостящийся статически
   на GitHub Pages (`reprepro` + GPG-подпись), чтобы пользователи получали
   автообновления через `apt upgrade`.
3. Автоматизировать релизы через `release-please`: Conventional Commits
   формируют release PR, его merge создаёт git-тег `vX.Y.Z` и GitHub Release,
   тег запускает CI-сборку пакета и публикацию в репозиторий.

Версией продукта считается версия бинарного crate'а `crates/pine-linux`.
Внутренние crate'ы (`pine-core`, `pine-git`, `pine-terminal`) помечены
`publish = false` и не имеют самостоятельной пользовательской версии.
`release-please` таргетирует `crates/pine-linux` и бампит его версию; сборка
внутри workspace идёт по path и не зависит от версий внутренних crate'ов.

## Обоснование

### Нативные пакеты

Нативные `.deb` сохраняют host CLI-инвариант: терминал запускает реальный
shell и реальные CLI-агенты (`codex`, `claude`, `pi`), установленные на host,
а `pine-git` вызывает системный `git` и работает с файлами пользователя без
посредников. Никаких скрытых ослаблений проверок (ADR 0001, ограничение №6):
sandbox-режимы и portal-ограничения не включаются по умолчанию.

### Собственный APT-репозиторий на GitHub Pages

GitHub Pages раздаёт репозиторий статически и бесплатно, а `reprepro` ведёт
структуру `pool`/`dists`, индексы `Packages` и подписанные `Release`/
`InRelease`. GPG-подпись гарантирует подлинность, а `apt` даёт пользователям
привычные автообновления без ручной загрузки файлов.

### Автоматизация релизов

Conventional Commits уже используются в истории репозитория (`feat:`, `fix:`,
`docs:`). `release-please` читает их, подсчитывает SemVer-бамп, готовит
release PR с changelog и обновляет `version` в `crates/pine-linux/Cargo.toml`
(и запись в `Cargo.lock`).
Merge PR единственная ручная операция; остальное — от git-тега до публикации
пакета — делает CI. Полный контроль над Rust-тулчейном: сборка идёт на свежем
`rustc` в GitHub Actions, а не на archive-`rustc` из дистрибутива.

## Рассмотренные альтернативы

### Flatpak

Отклонено: sandbox Flatpak ломает host CLI workflow: CLI-агентов нет внутри
рантайма, доступ к произвольным папкам пользователя и к host-процессам
требует `--filesystem=host` и `flatpak-spawn --host`, что незаметно ослабляет
process и filesystem проверки и нарушает ADR 0001 (ограничение №6 и условие
пересмотра). Это ровно тот случай, ради которого условие пересмотра записано.

### Launchpad PPA

Отклонено на старте. PPA собирается на buildd системным `rustc` из Ubuntu
archive, который сильно старше `rust-version = "1.96.1"`, особенно на 24.04;
сборка падает на MSRV-проверке, либо требует доставки своего тулчейна в
source package. Допустимо вернуться, если появится задача быть в «каноничном»
Ubuntu-канале и MSRV-конфликт будет решён.

### AppImage

Не выбран основным путём, но допустимая будущая опция. AppImage не вводит
sandbox и даёт portability без установки; может дополнить `.deb` для
пользователей вне Debian/Ubuntu-семейства.

### Managed-репозитории (Cloudsmith, packagecloud)

Не выбраны сейчас, но допустимая будущая опция, если поддержка собственной
GPG/Pages-инфраструктуры окажется дороже, чем hosted-репозиторий с готовой
подписью и инструкцией подключения.

### cargo-release

Отклонено: даёт ручной контроль версий, но не автоматизирует релиз из
Conventional Commits. Это расходится с целью — выпускать без ручного
редактирования версий и changelog.

## Последствия

Положительные:

- авто-релизы из обычных коммитов через release PR;
- автообновления у пользователей через `apt upgrade`;
- полный контроль над Rust-тулчейном и packaging-конвейером;
- версионирование продукта (бинарник `pine-linux`) одним release PR;

Отрицательные:

- нужно поддерживать GPG-ключ и инфраструктуру репозитория на GitHub Pages;
- охват только Debian/Ubuntu-семейства (другие дистрибутивы — через AppImage
  или отдельные пакеты в будущем);
- нет интеграции с GNOME Software из коробки — приложение появляется в меню
  только после установки пакета, а не из центра приложений по умолчанию.

## Ограничения реализации

1. `.deb` собирается на Ubuntu 24.04 (API-floor по `AGENTS.md` и
   `docs/development.md`) для архитектур `amd64` и `arm64`; один пакет
   работает и на 24.04, и на 26.04.
2. Поле `Depends` в control-файле точно отражает системные библиотеки:
   `libgtk-4-1`, `libadwaita-1-0`, `libgtksourceview-5-0`,
   `libvte-2.91-gtk4-0` (и `git` как `Recommends`).
3. GPG-ключ ротируется через subkeys; приватный ключ хранится только в
   CI-секретах.
4. Sandbox-режимы запуска не включаются по умолчанию.
5. Версией продукта считается версия `crates/pine-linux`; внутренние crate'ы
   (`pine-core`, `pine-git`, `pine-terminal`) помечены `publish = false` и не
   имеют самостоятельной версии. Версии в `crates/*/Cargo.toml` задаются явно
   (не через `version.workspace = true`), т.к. `release-please`
   (`cargo-workspace`-плагин) не поддерживает Cargo workspace inheritance для
   version. Релиз таргетирует `crates/pine-linux`.

## Условия пересмотра

Решение пересматривается, если выполняется хотя бы одно условие:

- появилось требование охвата sandbox-first систем (ChromeOS, Flatpak-only);
- core-инвариант host-CLI изменён, и sandbox перестаёт ему противоречить;
- собственная GPG/Pages-инфраструктура стала дороже hosted-репозитория
  (Cloudsmith, packagecloud) или Launchpad PPA.

В таком случае оцениваются Flatpak, AppImage, PPA или managed-репозиторий;
изменение оформляется новым ADR, а не неявной заменой канала дистрибуции.
